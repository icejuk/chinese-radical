# BLOOM — ออกแบบแผนที่คำใหม่ก่อนพัฒนา

วันที่: 19 ตุลาคม 2026
สถานะ: ข้อเสนอเพื่อรีวิว ยังไม่ได้แก้ UI หรือ deploy
ขอบเขต: แผนที่คำ การอ่านคำ การแตกกิ่ง และรายละเอียดบนมือถือ/คอม

## 1. เป้าหมายของหน้าจอ

ผู้เรียนต้องตอบได้ภายในไม่กี่วินาทีว่า “กำลังดูคำอะไร คำนี้มาจากไหน และไปต่อที่ตัวไหนได้” พร้อมอ่านจีน พินอิน ไทย และกดฟังได้ โดยเก็บกิ่งที่เปิดไว้บน canvas เดียวกัน

ภาพที่ผู้ใช้ส่งคือกรณีหลักของการออกแบบ: 学 → 学生 → 生 → 生活 และมี 日 แตกออกจาก 生日 อยู่ใกล้กัน ไม่ควรต้องซูมทั้งแผนที่จนตัวหนังสือเล็กเพื่อเข้าใจความสัมพันธ์นี้

## 2. วิเคราะห์จากภาพและโค้ดปัจจุบัน

| สิ่งที่พบ | ผลกับผู้เรียน | ต้นเหตุที่ตรวจพบ |
| --- | --- | --- |
| การ์ดเล็กและพินอิน/ไทยแทบอ่านไม่ได้ในภาพรวม | เห็นคำจำนวนมากแต่ใช้เรียนไม่ได้ | FocusMap scale ทั้ง world; fit-to-branch ไม่กำหนดระดับรายละเอียดตามซูม |
| เส้นทางที่อ่านไม่มีน้ำหนักเด่นพอ | ต้องไล่เส้นเองว่า 生活 มาจาก 生 | เน้นเฉพาะเส้นเข้า node ที่เลือก ไม่ใช่เส้นทางบรรพบุรุษทั้งสาย |
| กิ่งมีหลายทิศแล้ว แต่ยังดูเหมือนคำกระจาย | ไม่เห็นขอบเขตกิ่งและพื้นที่สำหรับแตกต่อ | tree.ts วางวง/พัดแล้วหลบเฉพาะกล่อง ยังไม่มี branch envelope หรือ edge–node collision |
| จุดพื้นหลังยังเด่นเมื่อการ์ดย่อ | ภาพรกโดยไม่มีข้อมูลเพิ่ม | dot grid ขนาดและความเข้มคงที่ |
| ทุกการ์ดมีข้อความบอกให้กดเหมือนกัน | ข้อมูลสำคัญแข่งขันกับคำสั่งซ้ำ | node hint แสดงทุก node |
| รูปร่าง การเน้น และตัวอักษรถูกแก้หลายรอบ | ควบคุมความสม่ำเสมอยาก | bloom.css มี selector ของ map ซ้ำหลายตำแหน่ง |
| กลุ่มหลักห่างมากเมื่อขยาย | การดูทั้งแผนที่ทำให้ย่อมากเกินไป | root anchor ใช้ระยะตั้งคงที่ 2,600 หน่วย |

ข้อจำกัดของหลักฐาน: ภาพและโค้ดยืนยันปัญหาด้านโครงสร้างได้ แต่ยังไม่ได้ทำ usability study กับผู้เรียนจริง จึงไม่อ้างว่ารูปแบบใหม่ผ่านการทดสอบผู้ใช้แล้ว

## 3. ทิศทางที่เลือก: กิ่งคำบนกระดาษโปร่ง

คง BLOOM สีเขียวอ่อน ตัวอักษรจีนเด่น และสีพีชสำหรับคำที่เลือก ลายเซ็นคือ “กิ่งโค้งที่บอกเส้นทางการเรียน” มีจังหวะพื้นที่ว่างและแตกหลายทิศตามพื้นที่จริง ข้อความตั้งตรงเสมอ

พิจารณา 3 วิธี:

- วงกลมสมมาตรทุกระดับ: ดูเรียบร้อยช่วงแรก แต่กิ่งลึกชนวงอื่นง่ายและยังแข็ง
- force layout ที่ขยับตลอด: กระจายได้ แต่คำหนีตำแหน่งเมื่อแตะ ทำให้ตามกิ่งยาก
- **กิ่งโค้งแบบคงตำแหน่งและแบ่งพื้นที่ตามขนาดกิ่ง — เลือกวิธีนี้**: วางอย่างมีจังหวะ โดยยังจำตำแหน่งเดิมได้เมื่อเปิดคำใหม่

คำว่าเป็นธรรมชาติหมายถึงมีพื้นที่ให้กิ่งเติบโต ไม่ใช่สุ่มตำแหน่ง หรือเพิ่มเส้นตกแต่งที่ไม่มีความสัมพันธ์จริง

## 4. องค์ประกอบหน้าจอที่เสนอ

### คอม: แผนที่เป็นพื้นที่หลัก รายละเอียดอยู่ข้างคำ

```text
┌ BLOOM    [ค้นหาคำจีน พินอิน หรือไทย…]                ช่วยเหลือ ┐
│ 学 → 学生 → 生 → 生活                    [ภาพรวม] [อ่านคำ]     │
├──────────────────────────────────────────────┬────────────────┤
│       日记      日历                          │ 生活           │
│          ╲      ╱                            │ shēnghuó       │
│            日                                │ ชีวิต          │
│              ╲                               │ [ฟัง] [ช้า]    │
│               生日          医生             │                │
│                   ╲        ╱                 │ แตกกิ่งจาก     │
│                     生 ─── 生活 ← selected   │ [生] [活]      │
│                  ╱      ╲                    │                │
│                学生      生气                │ [ฝึกเขียน]     │
│               ╱                              │ ดูรายละเอียด  │
│              学                  [− 100% +]   │                │
└──────────────────────────────────────────────┴────────────────┘
```

เป็น wireframe แสดงลำดับชั้น ไม่ใช่พิกัด layout สุดท้าย คำข้างเคียงจริงขึ้นกับชุดข้อมูลและกิ่งที่เปิด ไม่มีเส้นใหม่เพื่ออ้างว่าความหมายเหมือนกัน

### มือถือ: อ่านพื้นที่ใกล้คำที่เลือก บน canvas เดิม

```text
┌ BLOOM                         ค้นหา ┐
│ … 学生 → 生 → 生活                  │
│                                    │
│        生日                        │
│           ╲                        │
│             生                     │
│               ╲                    │
│                生活                │
│              shēnghuó              │
│                ชีวิต               │
│                                    │
│ [ภาพรวม] [อ่านคำ]          [−] [+]  │
├────────────────────────────────────┤
│ 生活  shēnghuó · ชีวิต         [×] │
│ [ฟัง] [ช้า]   แตกกิ่ง [生] [活]     │
│ [ฝึกเขียน]             รายละเอียด │
└────────────────────────────────────┘
```

ใช้พื้นที่ที่เหลือจริงหลัง header, controls, navigation และ dock; dock ย่อเริ่มต้นเป้าหมายประมาณ 144–184px แต่อนุญาตให้สูงขึ้นตามฟอนต์และการตัดบรรทัด ไม่บังคับความสูงจนข้อความล้น

ไม่ย่อทุกคำให้พอดีจอมือถือ คำที่อยู่นอกจออยู่ใน canvas เดิมและลากไปหาได้; ปุ่มภาพรวมช่วยบอกทิศทาง การแตะคำจะกลับสู่ขนาดอ่านได้

## 5. Visual system และ CSS

### สี

| Token | ค่าเสนอ | หน้าที่ |
| --- | --- | --- |
| --map-paper | #F7FAF4 | พื้นแผนที่เขียวเกือบขาว |
| --map-surface | #FFFFFF | การ์ด |
| --map-ink | #203E32 | จีนและไทย |
| --map-muted | #51665A | พินอินและข้อความรอง |
| --map-line | #CAD8CB | ขอบ/เส้นที่ไม่ active |
| --map-active | #477455 | เส้นทางที่เลือกและ focus |
| --map-selected | #FBE6CE | พื้นคำที่เลือก |

สีประจำกลุ่มเดิมใช้เฉพาะเส้นกับจุดกำเนิด ลดการถมสีทั้งบริเวณ ไม่ใช้สีอย่างเดียวสื่อสถานะ: selected มีขอบหนาขึ้น ส่วน keyboard focus มีวง outline แยกต่างหาก ตรวจ contrast จริงหลังประกอบ UI

### ตัวอักษรและขนาด ณ ระดับอ่าน 100%

- จีน: `"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` ขนาดคำ 30px/1.25, ตัวตั้งต้น 40px/1.2, น้ำหนัก 400–500
- ไทย: `"Thonburi", "Noto Sans Thai", "Sukhumvit Set", sans-serif` ขนาด 15px/1.5
- พินอิน: `system-ui, sans-serif` ขนาด 16px/1.4 ให้พื้นที่เหนือสระเพียงพอสำหรับวรรณยุกต์
- ปุ่ม/label: 14px ขึ้นไป; target การแตะอย่างน้อย 44×44 CSS px
- ไม่เพิ่ม font download ในรอบแรก ตรวจ fallback บนแต่ละระบบและข้อความยาวก่อนตัดสินใจ bundle font

### รูปทรงและระยะ

- Word card: ความกว้างเริ่มต้น 156–188px, min-height 112px, padding 12–16px, radius 16px; คำยาวต้องวัดขนาดก่อนส่งเข้า layout
- Character hub: ทรงมนแบบ seed ใช้ radius `46% 54% 48% 52%`; ขนาดเริ่มต้น 112–128px แต่ไม่บีบคำแปล
- เงาเฉพาะ selected/hover: `0 4px 16px rgb(32 62 50 / 8%)`; การ์ดปกติใช้ขอบ 1px
- ช่องว่างระหว่างขอบการ์ดอย่างน้อย 24px ในระดับอ่าน; เผื่อเส้นและ focus ring เพิ่ม
- ลบ hint ซ้ำบนทุกการ์ด; แสดงคำสั่งใน toolbar และรายละเอียดของคำที่เลือก
- dot grid ลดเป็นจางมากในระดับอ่าน และซ่อนในภาพรวม ไม่เพิ่ม texture/gradient ตกแต่ง

### โครง CSS ที่เสนอ

แยก `map.css` ให้เป็นเจ้าของ map styles เพียงไฟล์เดียว ย้ายกฎเดิมและลบเฉพาะกฎ map ที่ซ้ำจาก bloom.css ไม่เติม override อีกท้ายไฟล์

```css
.bloom-map {
  --map-paper: #f7faf4;
  --map-surface: #fff;
  --map-ink: #203e32;
  --map-muted: #51665a;
  --map-line: #cad8cb;
  --map-active: #477455;
  --map-selected: #fbe6ce;
  background: var(--map-paper);
  color: var(--map-ink);
}
.bloom-map__node {
  display: grid;
  place-content: center;
  gap: 4px;
  padding: 12px 16px;
  border: 1px solid var(--map-line);
  border-radius: 16px;
  background: var(--map-surface);
}
.bloom-map__node[data-selected="true"] {
  background: var(--map-selected);
  border: 2px solid var(--map-active);
}
.bloom-map__node:focus-visible {
  outline: 3px solid var(--map-active);
  outline-offset: 4px;
}
.bloom-map__edge { vector-effect: non-scaling-stroke; }
```

ใช้ CSS custom properties, Grid สำหรับ shell/dock และ absolute positioning เฉพาะ node ที่ layout คำนวณไว้; SVG สำหรับเส้น ไม่เพิ่ม UI framework หรือ animation library ในงานนี้

แยก `data-kind`, `data-selected`, `data-on-path`, `data-detail-level` ชัดเจนเพื่อไม่ให้ selector ทับกัน ไม่ใช้ opacity ลดทั้งการ์ดจนข้อความรองอ่านไม่ได้

## 6. การซูมและการอ่าน: ต้องแก้พฤติกรรมพร้อมหน้าตา

มี 2 ระดับการนำเสนอใน canvas เดียว:

1. **อ่านคำ:** จีน พินอิน ไทยครบ ขนาดข้อความบนจอมีขั้นต่ำพินอิน 16px/ไทย 15px เน้น selected, parent และคำข้างเคียงที่วางได้ ไม่ auto-fit ทุก descendants หลังแตกกิ่ง
2. **ภาพรวม:** มองรูปร่างกิ่งและทางที่เคยเปิด ลดการ์ดเป็น label จีน/จุดกำเนิด ส่วนคำที่เลือกมีจีน พินอิน ไทยในแผงขนาดคงที่ การแตะ label กลับสู่ระดับอ่าน ไม่แสดงพินอินขนาดจิ๋วให้ดูเหมือนอ่านได้

ข้อแลกเปลี่ยนที่ต้องเห็นก่อนทำ: ในภาพรวมไม่ได้แสดงพินอินและไทยทุกคำพร้อมกัน แต่ข้อมูลยังเข้าถึงได้จากทุกคำผ่านการเลือก และมีครบในระดับอ่าน หากต้องการทุก label ครบพร้อมกันต้องยอมใช้ canvas ใหญ่และลากดู ไม่สามารถย่อทุกอย่างลงจอเล็กโดยยังอ่านเท่าเดิมได้

- เกณฑ์เปลี่ยนรายละเอียดคำนวณจากขนาดข้อความที่ render จริง ไม่อาศัยแค่เลขเปอร์เซ็นต์
- ช่วงเปลี่ยนใช้ hysteresis ป้องกัน flicker ขณะ pinch
- selected overlay/dock อยู่ใน screen space ไม่ถูก scale ตาม world
- zoom รอบ pointer/pinch center; wheel ปกติเลื่อนพื้นที่, Ctrl/Meta+wheel ซูม พร้อมปุ่ม +/− สำหรับทุกอุปกรณ์ (ต้องทดลอง trackpad ก่อนสรุปค่า gesture)
- ไม่ยึด scale ของ overview เป็นตำแหน่งอ่านครั้งต่อไป

## 7. Layout ของกิ่งและเส้น

1. วัด card bounds ตาม typography และเนื้อหาจริงก่อนจัดกิ่ง รวม padding, outline และพื้นที่อ่าน
2. เก็บ anchor ของ node ที่เปิดแล้ว; สงวนพื้นที่กิ่งเป็น envelope ตามขนาด subtree แทนการพึ่ง ring index อย่างเดียว
3. เสนอมุมกิ่งตามพื้นที่ว่างรอบ parent และทิศออกจากต้นทาง มุมไม่จำกัดซ้าย/ขวา ไม่บังคับทุก parent เป็นวงกลม
4. ให้คะแนน candidate จาก node overlap, เส้นตัดการ์ด, edge crossing, ความยาวเส้น และการขยับ anchor เดิม โดยให้ node overlap/เส้นตัดการ์ดเป็นข้อห้าม
5. วางคำใหม่ในพื้นที่ว่างใกล้กิ่งก่อนขยาย radius; ถ้าที่ไม่พอขยายเฉพาะพื้นที่กิ่งใหม่ ไม่เขย่าทั้งแผนที่
6. เชื่อมจากขอบรูปทรงจริง เส้น cubic Bézier หลีกการ์ดอื่น เน้น selected ancestry ทั้งเส้นทาง 2–2.5px; เส้นปกติ 1–1.25px
7. แสดง label ความสัมพันธ์ในรายละเอียดเมื่อจำเป็น เช่น “生活 มีตัว 生” ไม่ใช้เส้นเพื่อสื่อว่าคำประกอบอธิบายความหมายได้ตรงตัวเสมอ
8. ปรับ root groups จากระยะตั้งคงที่เป็น packing ตาม envelope; ทำหลัง local branch อ่านง่ายแล้ว เพื่อไม่เปลี่ยนทุกอย่างในรอบเดียว

การกันชนต้องตรวจหลัง label เปลี่ยนระดับซูมด้วย ถ้าพื้นที่ภาพรวมไม่พอให้ลดจำนวน label รอบนอกที่แสดงพร้อมตัวบอกจำนวนคำในกิ่ง แต่ยังคงโครงสร้างและสถานะกิ่งไว้ ไม่มีการแบ่งหน้า

## 8. Interaction ที่ต้องชัดเจน

| การกระทำ | สิ่งที่เห็นทันที |
| --- | --- |
| แตะคำ | selected + เน้นสายต้นทาง + รายละเอียดพร้อมเสียง; ไม่เล่นเสียงอัตโนมัติ |
| แตะตัวอักษรเพื่อแตกกิ่ง | กิ่งใหม่ปรากฏใกล้ต้นทาง + ข้อความแจ้งจำนวนคำเพิ่มที่ไม่บังแผนที่ |
| แตะคำเดิม | เปิดรายละเอียดได้อีก แม้ URL ไม่เปลี่ยน |
| ไม่มีคำใหม่ | ข้อความตรงไปตรงมาว่า “ยังไม่มีคำใหม่ในกิ่งนี้” พร้อมเสียง/เขียน |
| ปิดรายละเอียด | กลับอ่าน canvas ณ ตำแหน่งเดิม ไม่ยุบกิ่ง |
| ดูภาพรวม | เห็นขอบเขตกิ่งปัจจุบันและเส้นทางที่เลือก; มีปุ่มกลับอ่านคำชัดเจน |
| Back/Forward/เปิด deep link | คืนคำและกิ่งตาม URL; ขนาดอ่านไม่ถูกย่อเพราะกิ่งลึก |

Motion: pan 220–280ms, reveal 160–200ms, ไม่มี bounce/float ตลอดเวลา; `prefers-reduced-motion` ยกเลิกการเคลื่อนไหว; เริ่ม drag ใหม่ต้องยกเลิก animation ทันที

## 9. Responsive และ accessibility

- ≥1100px: canvas + detail rail 300–336px
- 701–1099px: canvas เต็มพื้นที่ รายละเอียดแบบย่อใต้ toolbar หรือ dock ที่ไม่ทับ selected
- ≤700px: canvas ใช้พื้นที่จอที่เหลือ; dock ย่ออยู่เหนือ navigation/safe area; รายละเอียดขยายเมื่อผู้ใช้สั่ง
- ใช้ ResizeObserver วัด panel/viewport แทนการหัก dock 280px แบบตายตัว
- breadcrumb ตัดเฉพาะช่วงต้นเมื่อยาว ยังแสดง parent และ selected ครบ; เปิดเส้นทางเต็มได้
- Keyboard focus ต้องเคลื่อนกล้องให้ node มองเห็น; Tab order ตามสายคำ ไม่ใช่สุ่มพิกัด
- แยก state คำที่เลือกกับ keyboard focus; voice status ใช้ aria-live แบบสุภาพ
- 200% text zoom ต้องไม่มีข้อความหาย; label ภาพรวมเล็กต้องมีทางเลือกผ่านค้นหา/เส้นทางที่อ่านได้

## 11. เกณฑ์รับงานของ design นี้

- ใช้ fixture จากภาพจริง 学 → 学生 → 生 → 生活 พร้อม 日 ที่เปิดจาก 生日; เพิ่ม 人 16 คำ และกิ่งลึกเพื่อจับกรณี layout หนาแน่น
- ตรวจ 320, 390, 768, 1024, 1440px ทั้งภาพรวม/อ่านคำ/dock เปิด-ปิด
- ระดับอ่าน: selected, พินอิน, ไทย ไม่ถูกบัง/ตัด; target การแตะ ≥44px
- เห็น selected ancestry ชัดโดยไม่ต้องไล่ทุกเส้น; เส้นไม่ทะลุ unrelated card
- ไม่มี node overlap; แตกกิ่งแล้ว anchor เดิมไม่กระโดด; ไม่แบ่งหน้าหรือเปลี่ยน canvas
- ภาพรวมไม่แสดงตัวหนังสือจิ๋วเป็นเนื้อหาที่ต้องอ่าน; กลับอ่าน selected ได้ใน 1 action
- แตะซ้ำ, กิ่งว่าง, deep link, Back/Forward, ฟังปกติ/ช้า และเปิดฝึกเขียนยังทำงาน
- ตรวจ reduced motion, focus visibility, text zoom และ contrast จาก UI ที่ render จริง
- หลักฐานต้องมี screenshot หลัง animation จบ และตรวจโดยสายตาด้วย ไม่ถือว่าผ่านเพียงเพราะไม่มี overlap ใน automated check

เอกสารนี้เป็น design และเกณฑ์รับงาน ยังไม่ใช่ผลทดสอบ งานรอบนี้เปลี่ยนเฉพาะเอกสาร; ขั้นต่อไปคือ preview A เพื่อรีวิวก่อนแก้ตัวแอป
