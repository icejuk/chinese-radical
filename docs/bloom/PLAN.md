# BLOOM — แผนพัฒนาแอปจริง

วันที่ 18 ตุลาคม 2026 · repo icejuk/chinese-radical · branch feat/bloom-learning

## เป้าหมายและขอบเขต

ใช้ BLOOM ธีมเดียวในแอป React จริง เน้นแผนที่คำเป็นหน้าแรก รองรับคอมและมือถือจีนตัวย่อ ทุกคำมีพินอิน ไทย และเสียง มีคำสู่ประโยค แบบทบทวน ภารกิจพูด และลำดับขีด/ฝึกเขียนเป็นเครื่องมือเสริม

ไม่รวมแผนที่ความจำ ระบบบัญชี การบันทึกระยะยาว SRS ใหม่ หรือการให้คะแนนเสียงอัตโนมัติ ระบบเดิมที่มีอยู่ต้องไม่ถูกลบข้อมูลโดยไม่ได้รับอนุญาต

ใช้ 54 คำ / 16 ตัวอักษร / 4 กลุ่มเป็น seed รอบแรก ไม่ถือว่าจำ 2,000 ตัวแล้วพูดได้ ไม่คัดลอก HTML prototype ลง production ทั้งก้อน และไม่ย้ายไฟล์ฟอนต์ขนาดใหญ่ของต้นแบบโดยตรง

## สถาปัตยกรรมจาก repo จริง

React 18 + TypeScript + Vite + PWA + Vitest ใช้ src/components/StrokePad.tsx และ src/lib/tts.ts ต่อได้ ข้อมูลเดิมใน src/data/hanzi.ts เป็นตัวอักษรและคำประกอบ ยังไม่ใช่ word graph ที่พร้อมใช้ทั้งคลัง จึงเพิ่ม src/features/bloom แยก model, graph helpers, layout, UI และบทเรียน

- typed edges แยกตัวจีนอยู่ในคำกับส่วนประกอบ ไม่อ้างว่าความสัมพันธ์ทุกเส้นคือรากศัพท์
- ทุกคำของตัวตั้งต้นอยู่บนผืนเดียว ไม่แบ่งหน้า แตกกิ่งแล้วเก็บเส้นทางเดิมไว้ ยุบกิ่งได้
- React ดูแล state กับ lifecycle ไม่ใช้ document.innerHTML เหมือน mock
- router ต้องรองรับ URL โดยตรงและ browser back แยกชื่อ route ใหม่ไม่ชน #learn/#practice/#explore เดิม กำหนด compatibility ก่อนเปลี่ยน default
- โครง BLOOM: #f3f8ee พื้น, #ffffff การ์ด, #246d57 ปุ่ม, #173e35 ตัวอักษร, #d5e4d5 เส้น, #fce1c9 จุดที่เลือก
- มือถือเมนูล่าง คอมเมนูด้านข้าง รายละเอียดต้องไม่บังคำ และตำแหน่งคำไม่เคลื่อนเมื่อเลือกเฉพาะคำ

## เกณฑ์รับงาน

AC-MAP: ค้น/แตกคำ/ย้อนกลับ/ซูม ใช้ได้ ไม่มีการ์ดทับทั้งแนวตั้งและแนวนอนที่ 320, 375, 390, 768, 1024, 1440px คำ 水 เข้าถึงครบ 7 คำบนผืนเดียว
AC-LANG: คำและประโยคมีจีน พินอิน ไทยตรงกัน ข้อมูลที่ยังไม่ตรวจภาษาต้องระบุสถานะและไม่อ้างเป็นคลังที่ตรวจครบแล้ว
AC-AUDIO: มีสถานะโหลด/ผิดพลาด หยุดเสียงเดิมก่อนเริ่มใหม่ เสียงปกติ/ช้าเล่นจากรายการเดียวกัน
AC-WRITE: โหลดลำดับขีด local ได้ เปลี่ยนตัวกลาง animation ได้ ไม่ซ้อน SVG และใช้บน touch ได้
AC-REVIEW: ไม่เผยคำก่อนเฉลย ตรวจคำตอบครั้งเดียว ไม่บวกคะแนนซ้ำ จากนั้นทำรอบใหม่ได้
AC-SPEAK: ขอไมค์เมื่อกดอัดเท่านั้น ไม่มี upload หยุด track และคืน Blob URL เมื่อออก อนุญาต/ปฏิเสธ/ไม่รองรับต้องไปต่อได้ ไม่มีคะแนนเสียงปลอม
AC-UX: คีย์บอร์ดใช้งานได้ โฟกัสมองเห็น ปุ่มหลักแตะง่ายตามพื้นที่จริง ซูม/ลากไม่กลายเป็นคลิก ไม่มี horizontal page scroll ที่ความกว้างที่รองรับ
AC-PERF: เป้าหมายเริ่มต้น production LCP ≤2.5s, CLS ≤0.1 ในการวัดที่บันทึกอุปกรณ์/เครือข่ายไว้ ต้องยืนยันด้วยผลจริงก่อนอ้างว่าผ่าน; ระหว่างลากจอต้องไม่ค้างหรือจัดผังใหม่ทุกเฟรม
AC-RELEASE: npm test + npm run build ผ่าน ตรวจ PWA อัปเกรดจาก cache เวอร์ชันเก่าและ smoke บน iOS Safari / Android Chrome / desktop Chrome, Safari หรือ Edge ปัจจุบัน

## QA concerns

อ้างอิง requirement ในแชตและโค้ด repo ไม่ได้ดึง Jira ไม่มี backend ใหม่ในขอบเขตนี้

Critical: มีไมโครโฟนเกี่ยวข้องความเป็นส่วนตัว จึงต้องไม่ส่งเสียงและปิด track ทุก exit; Actuating: ไม่มี side effect ภายนอก; Blast radius: กลางถึงสูงสำหรับ navigation, CSS, TTS และ PWA ที่ผู้ใช้เดิมใช้ร่วมกัน

- dependency เสียงหรือไมค์พัง: แสดง retry/ฝึกตามข้อความได้ ไม่อัดเอง ไม่สร้างคะแนนสำเร็จ
- ตรวจใน production: สถานะ mic ชัด, track cleanup ที่ทดสอบได้, ตรวจ network ไม่มีเสียงอัปโหลด ไม่เก็บเสียงใน log/analytics
- PWA เก่าอาจทำให้ JS/CSS/ข้อมูลคนละเวอร์ชัน ต้องทดสอบ update ไม่ใช่แค่ fresh install
- คลังคำต้นแบบไม่ใช่ข้อมูลที่ตรวจภาษาทั้งหมด ต้องตรวจพินอิน เสียงวรรณยุกต์ในประโยค คำแปล/การใช้ และสิทธิ์เสียง/ฟอนต์ก่อนปล่อย
- speech scoring, บัญชี และขยาย 2,000 ตัวไม่รวมในประมาณการ เพิ่มเป็นงานใหม่หลังเลือกแหล่งข้อมูลและข้อตกลงใช้ข้อมูล
- โค้ดเดิมยังมี SRS/localStorage ใช้ fallback อย่างปลอดภัยและไม่ลบ progress เก่าโดยไม่จำเป็น

## สถานะล่าสุด — รอบทำฟังก์ชันครบ

- P0/P1: โครง BLOOM, ค้นหา, ต้นไม้ต่อเนื่อง, แตก–ยุบกิ่ง, URL/back และรายละเอียดมือถือพร้อมใช้
- P2: เสียงปกติ/ช้า พร้อม error/retry และลำดับขีด/ลากเขียนเปิดจากรายละเอียดคำได้ ทุกตัวใน 97 คำมีไฟล์ขีด local
- P3: คำสู่ประโยค 5 รูปแบบ และทบทวนครบวงจร 3 ข้อ/รอบ พร้อมเฉลย คะแนน และเริ่มใหม่
- P4: 2 สถานการณ์/6 คำถาม ตัวอย่างคำตอบ อัด–หยุด–ฟังในเครื่อง ไม่ส่งไฟล์ และ cleanup ไมค์/Blob URL
- P5: 55 automated tests + production build ผ่าน, browser journeys และ responsive 24 รูปแบบผ่าน; ปิด preview server แล้ว reload และเปิดลำดับขีด/ประโยคจาก cache ได้
- ข้อมูลล่าสุด 97 คำ / 94 ตัวอักษร; ไม่เหลือตัวอักษรที่ปิดอยู่ภายในคำชุดนี้
- ยังไม่ใช่การรับรอง UAT บนอุปกรณ์จริง: microphone recording จริงบน iOS/Android, อัปเกรดจาก production cache รุ่นเก่า และเป้าหมาย LCP/CLS บนอุปกรณ์เป้าหมาย ยังต้องตรวจเพิ่ม ไม่อ้างว่าผ่านจากการจำลอง
- ยังไม่ได้ commit/push/deploy; รายละเอียดผลและข้อจำกัดอยู่ใน VERIFICATION.md

## งานขยายคลัง 2,000 ตัว

เป้าหมายระยะถัดไปยังอยู่ แต่ไม่รวมใน 36–50 ชั่วโมง ต้องเลือกแหล่งข้อมูลที่ใช้ต่อได้และกำหนดคุณภาพคำแปล/เสียงก่อนจึงประเมินได้จริง โดยนำเข้าเป็นชุด ตรวจ duplicate/ความสัมพันธ์/ไฟล์เสียงและลำดับขีด และให้ผู้รู้ภาษาตรวจตัวอย่างก่อนขยาย ไม่กำหนดวันส่งคลัง 2,000 ตัวจาก mock 16 ตัว

## Test cases

BLOOM-test-cases.xlsx มี 43 Web cases และ 6 E2E journeys พร้อมช่องสถานะ ผลจริง และหลักฐาน ผลรายเคสแยกสิ่งที่ตรวจแล้วออกจาก Not run โดยอ้างหลักฐาน จึงไม่ใช่การรับรอง production ทุกอุปกรณ์
