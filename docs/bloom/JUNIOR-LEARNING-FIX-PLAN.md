## 4. งาน A — ไม่เฉลยแบบฝึกฟังก่อนตอบ

### ปัญหา

LearningHub แสดง dropdown `学生 · xuésheng · นักเรียน` ตลอดเวลา ขณะ reviewPool นำคำที่เลือกมาเป็นข้อแรก จึงเห็นคำตอบก่อนฟัง

### พฤติกรรมที่ต้องได้

1. หน้าเตรียมฝึกเลือกกลุ่มและคำได้ตามเดิม มีปุ่ม “เริ่มฝึก N คำ” (N คือจำนวนข้อรอบนี้ สูงสุด 3)
2. เมื่อเริ่ม ให้แทน picker ด้วยแถบ “ชุดฝึก · ข้อ 1/3” และปุ่ม “เปลี่ยนชุดฝึก” ไม่มีชื่อคำปัจจุบัน/พินอิน/คำแปล/เสียงคำศัพท์แอบอยู่ในแถบ
3. หน้าคำถามมีเสียงโจทย์ ตัวเลือกความหมาย และตรวจคำตอบ
4. จีน พินอิน ไทยของเฉลยแสดงหลังตรวจคำตอบเท่านั้น
5. ปุ่ม “เปลี่ยนเป็นดูตัวจีน” เป็นโหมดอ่านที่ผู้เรียนตั้งใจเลือก ใช้ชื่อชัดเจน ไม่แสดงคำแปลก่อนตรวจ
6. เปลี่ยนชุดฝึกระหว่างรอบ = ออกจากรอบเก่าและเริ่มคะแนนใหม่ ไม่รวมคะแนนสองชุด

### วิธี implement

- เพิ่มสถานะ setup/answering ในส่วน review หรือยกสถานะ started ไป LearningHub เพื่อควบคุม picker อย่าใช้ CSS ซ่อนเฉพาะภาพแต่ปล่อยเฉลยใน accessibility tree
- แยก markup ตัวเลือกคำจากแถบสถานะระหว่างทำข้อสอบ เฉลยไม่ควรอยู่ใน title/aria-label ของปุ่มฟัง
- ให้ pool และ selected word เป็น snapshot ของรอบที่เริ่มแล้ว ไม่ให้เปลี่ยนกลางข้อ
- ปิด/ยุบผลค้นหากลางเมื่อเริ่มฝึก ป้องกันคำที่เลือกค้างเหนือโจทย์
- คง reducer ที่ป้องกันตรวจซ้ำและเลือกคำตอบหลังตรวจไว้

## 5. งาน B — แบ่งชุดทบทวนให้ครบก่อนวนใหม่

### ปัญหา

`round * 3 % pool.length` กับ `slice(offset, offset + 3)` ทำให้กลุ่ม 4 คำเป็น 1–3 → 4 → 3–4 → 2–4 แทนที่จะจบหลังคำที่ 4

### วิธี implement

ย้าย logic แบ่งชุดไป pure function ใน `lessons.ts` เช่น:

```ts
export function splitReviewBatches<T>(items: readonly T[]): T[][] {
  const batches: T[][] = []
  for (let i = 0; i < items.length; i += 3) {
    batches.push(items.slice(i, i + 3))
  }
  return batches
}
```

- ReviewLesson เก็บ `batchIndex` เริ่ม 0, ใช้ batches[batchIndex] เป็นโจทย์ อย่า modulo กลางรอบ
- รอบสุดท้ายมี 1 หรือ 2 ข้อได้ แสดง denominator ตามจริงทุกจุด
- จบ batch ที่ยังมีชุดถัดไป: ปุ่ม “ฝึกชุดถัดไป”
- จบ batch สุดท้าย: แสดง “ฝึกครบ N คำแล้ว” และปุ่ม “เริ่มชุดคำนี้ใหม่” ซึ่งตั้ง batchIndex=0 และรีเซ็ตคะแนน
- ปุ่ม “ทบทวนชุดเดิม” รีเซ็ตเฉพาะ batch ปัจจุบัน
- เมื่อ scope/word เปลี่ยน ให้สร้าง batches ใหม่และกลับ setup
- pool ว่างต้องแสดง empty state พร้อมเปลี่ยนชุด ไม่อ่าน question.id จาก undefined
- UI ต้องใช้ helper เดียวกับที่ทดสอบ ห้ามเขียน logic แยกใน JSX จน test ผ่านแต่หน้าเว็บยังผิด

ผลที่ต้องได้: 4 คำ → [1,2,3], [4], จบ; 7 คำ → [1,2,3], [4,5,6], [7], จบ; 149 คำ → 50 batches โดย batch สุดท้ายมี 2 ข้อ

## 6. งาน C — เริ่มสถานการณ์ใหม่ต้องรีเซ็ตเสียงจริง

### ปัญหา

RecorderControl ใช้ key เป็น sceneId:index เมื่อฝึกคำเดียว index ยังคง 0 หลังเริ่มใหม่ React จึงไม่สร้างเครื่องอัดใหม่ เสียงอัดเดิม/สถานะเดิมยังอยู่ จุดนี้พบจากโค้ด ไม่ใช่ผลทดสอบไมค์จริงของรอบรีวิว

### วิธี implement ที่แนะนำ

- เพิ่ม `attemptId` ใน SpeakingLesson เริ่ม 0
- ทำ handler กลาง `restartAttempt()` เรียก stopSound(), ซ่อนตัวอย่าง, เพิ่ม attemptId
- key ของ RecorderControl ใช้ sceneId:index:attemptId
- ถ้า AudioPlayer มี playing state ภายใน ให้รวม attemptId ใน key ของตัวเล่นคำถาม/ตัวอย่างด้วย เพื่อ reset UI ไม่ใช่หยุดเสียงอย่างเดียว
- เริ่มสถานการณ์ใหม่ตั้ง index=0 แล้วเรียก restartAttempt; ไปคำถามถัดไปหรือเปลี่ยน scene ต้องหยุดเสียง/cleanup เช่นกัน
- การ remount จะเรียก LocalRecorder.dispose() ของตัวเก่า ซึ่งต้องหยุด tracks/timer และ revoke blob URL คงกลไก version ที่ป้องกัน permission resolve ช้าไว้
- ห้ามแก้โดยเรียก controller.stop() อย่างเดียว เพราะ stop สร้างเสียงพร้อมฟัง แต่ restart ต้องล้างเสียงเก่า
- ปุ่มเริ่มใหม่ต้องทำงานแม้อยู่ระหว่าง requesting / recording / ready
- ไม่เริ่มอัดใหม่อัตโนมัติหลัง reset ผู้ใช้ต้องกดเริ่มอัดเอง

- คำสู่ประโยคและฝึกพูดแสดง context bar จีน+พินอิน+ไทยแบบย่อ ค่า default ปิด picker

- ภายใน panel มีตัวกรองตัวตั้งต้น และช่องค้นหาคำฝึกด้วยจีน/พินอิน/ไทย เพื่อไม่ต้องเลื่อน 149 options
- reuse การ normalize/search ที่มีอยู่ถ้าเหมาะสม ตรวจให้แน่ใจว่าผลค้นหาเป็นคำใน scope ไม่ใช่ผลแผนที่ที่เปลี่ยนหน้า
- ไม่พบคำให้แสดง “ไม่พบคำในกลุ่มนี้” + ล้างค้นหา อย่าเปลี่ยน scope เป็นทั้งหมดเอง
- หน้าบทเรียนย้าย global map search ออกจากพื้นที่หลัก ให้เปลี่ยนคำผ่าน panel นี้; หน้า map ยังคง search เดิม
- review ใช้แถบสถานะตามงาน A แทน context bar ที่มีคำตอบ
- desktop จำกัดความกว้างเนื้อหาให้ติดตามสายตาง่าย ไม่ยืด selector เต็มจอ

### CSS specification

ใช้ธีม dark เดิม ไม่ redesign ชุดสีใหม่ กำหนด token ภายใต้ `.bloom-app` หรือใช้ token เดิมที่ตรงกัน:

| raised surface | #202a3f |

- ชื่อ class ใหม่เสนอ `.bl-practice-context`, `.bl-practice-change`, `.bl-practice-panel`, `.bl-speaking-mode` ใช้ prefix เดิม
- layout ใน bloom.css, สีธีมใน orbit.css; ตรวจ cascade ของ `.bl-practice-picker` ที่มีอยู่ก่อนเพิ่ม rule ห้ามต่อ override ซ้ำหลายท้ายไฟล์
- content max-width ประมาณ 960px; lesson card ประมาณ 720px; จัดกลาง มี padding 16px มือถือ / 24px desktop
- context bar ใช้ grid `minmax(0,1fr) auto`; Chinese/pinyin/ไทยอยู่ใน cell ซ้ายและ wrap ได้ ไม่ ellipsis คำอ่านจนหาย
- ขนาดจีนในโจทย์ `clamp(28px, 5vw, 40px)`; พินอิน/ไทย 16–18px; line-height 1.5–1.7; label ไม่น้อยกว่า 14px
- ≤700px เป็นคอลัมน์เดียว ปุ่มกลุ่ม wrap ได้; ตั้ง min-width:0 ให้ grid children; ไม่มี fixed height ที่ตัดข้อความ
- เผื่อ padding-bottom สำหรับ bottom nav + safe-area-inset-bottom; ปุ่มตรวจ/อัดต้องเลื่อนมาเห็นได้โดยไม่ถูก nav ทับ
- transition สี/opacity 120–180ms; เคารพ prefers-reduced-motion; ไม่ใช้ transform scale กับทั้งหน้าเพื่อให้พอดีจอ
- focus-visible ชัดเจน เช่น outline 2px accent + offset 3px; selected state ใช้ทั้ง aria-pressed และลักษณะขอบ/พื้นหลัง

เกณฑ์ layout: ที่ 390×844 หลังเข้า speaking ควรเห็นโจทย์และปุ่มฟังโดยไม่ต้องเลื่อนผ่าน selector; ที่ 320×780 ยอมให้เลื่อนตามเนื้อหาได้แต่ต้องไม่ overflow แนวนอน/ตัดไทย/ปุ่มโดน nav บัง

## 8. งาน E — เปลี่ยนรูปแบบแต่ไม่เปลี่ยนคำโดยพลการ

- เพิ่ม helper คืนรูปแบบที่ใช้กับ wordId ได้: authored example ถ้ามี + patterns ที่มีคำนั้น + meaning fallback
- แสดงแท็บเฉพาะรูปแบบที่รองรับคำปัจจุบัน การเปลี่ยนแท็บเปลี่ยน setId อย่างเดียว
- เอา fallback `item.words[0]` ออกจาก handler เปลี่ยนรูปแบบ ห้ามทำให้ 月亮 กลายเป็น 学生 เพราะกดแนะนำตัว
- “ลองเปลี่ยนคำนี้” ถือเป็นการเลือกคำโดยตั้งใจ แต่รายการต้องอยู่ใน scope ปัจจุบัน ถ้าอยากดูคำทุกกลุ่มให้มี action เปลี่ยน scope ชัดเจน
- แก้ choices ของ daily ไม่ให้แสดง 20 คำทุกกลุ่มเมื่อผู้ใช้กรอง 月
- query `set` ที่ไม่รองรับ word ให้ fallback ไป set ที่รองรับ โดยรักษา word/root; invalid word ให้ empty state หรือคำเริ่มต้นพร้อมข้อความ ไม่ throw
- ใช้ word จากแหล่งเดียว อย่าให้ local state word กับ URL คนละค่า
- ตรวจ hashchange/popstate ใน BloomApp: ขณะอยู่ section เดิมแต่ URL word เปลี่ยน ต้อง trigger render ด้วย state ของ route/lesson params ไม่พึ่ง setSection ค่าเดิม
- เปลี่ยนคำจาก picker เป็น replaceState ได้ตามพฤติกรรมปัจจุบัน ไม่สร้าง history ต่อทุกตัวอักษรค้นหา; เปลี่ยนหน้าใช้ history เดิม
- ทดสอบ refresh, Back/Forward และกลับแผนที่ผ่านปุ่ม “ดูคำบนต้นไม้” ว่าถึงคำถูกตัวและกิ่งเดิมไม่หาย

## 9. งาน F — ฝึกพูดมีทางเริ่ม และเติมเนื้อหาอย่างตรวจได้

### โหมดฝึกพูด

- default “พูดตาม”: แสดงตัวอย่างจีน+พินอิน+ไทยก่อน ปุ่มฟังต้นแบบ แล้วอัดเสียง
- “ลองตอบเอง”: แสดงคำถาม, ซ่อนตัวอย่างจนกดดู, อัดแล้วฟังเทียบได้
- คำที่ยังไม่มีประโยคใช้จริง: โหมดพูดตามอ่านคำศัพท์ พร้อมข้อความ “กำลังฝึกออกเสียงคำ”; โหมดตอบเองเป็นตัวเลือกเสริม อย่าเรียกคำศัพท์เดี่ยวว่าเป็นประโยคตัวอย่าง
- สลับโหมดต้อง reset attempt ตามงาน C
- ไม่ให้คะแนนความถูกต้องของเสียง เพราะระบบยังไม่ได้วิเคราะห์เสียง

### เนื้อหา 116 คำที่เหลือ

1. สร้างรายการ missing จาก allPracticeWords ลบคำที่ dailyExamples/patterns รองรับ ห้ามคัดลอกเลข 116 ไปใช้เป็น logic
2. เก็บงานตรวจใน `docs/bloom/CONTENT-COVERAGE.md` (สร้างตอน implement) มี wordId, จีน, ประโยค, พินอิน, ไทย, ผู้ตรวจ/สถานะ
3. ทำทีละประมาณ 20–25 คำ เริ่มคำใช้ในชีวิตประจำวัน ไม่เพิ่มจำนวนศัพท์ใหม่ระหว่างเติมช่องว่าง
4. ทุกคำมีอย่างน้อย 1 ประโยคธรรมชาติที่มีคำเป้าหมาย พินอินตรงทั้งประโยค ไทยสื่อความหมายตรง และไม่ยากเกินจำเป็น
5. ให้ผู้รู้ภาษาจีนตรวจคำหลายเสียง น้ำเสียง/วรรณยุกต์ คำแปลตามบริบท และไวยากรณ์ ก่อนนับ ready; unit test ไม่สามารถรับรองความถูกภาษาจีน
6. เก็บข้อมูลที่ตรวจแล้วใน practice.ts; ถ้ายาวมากแยก `practiceExamples.ts` แล้ว import เข้ามา อย่าคัดลอกคนละชุดสำหรับสองหน้า
7. ใช้ selector กลางสำหรับประโยคที่แนะนำให้ SentenceLesson และ speakingFor ใช้ชุดเดียวกัน
8. แก้ test ที่ hardcode dailyExamples.size=20 ให้ตรวจ coverage/valid record ตาม milestone; เมื่อจบต้อง assert ทุกคำมีประโยคจริง
9. อัปเดต README และ LEARNING-INTEGRATION ตามยอดที่ตรวจผ่านจริง อย่าประกาศครบจากจำนวน draft

### วิธีแบ่ง automated กับ manual

- Vitest: batch helper, reducer, compatible sets, coverage และ recorder lifecycle ด้วย dependency mocks เดิม
- เพิ่ม component integration test เฉพาะถ้ามี test harness ที่รองรับอยู่แล้ว; repo ปัจจุบันไม่มี React Testing Library ใน package.json ถ้าจะเพิ่มให้บันทึก dependency และเหตุผล ไม่อ้างว่า pure unit test ตรวจ DOM แล้ว
- Browser manual: เฉลยใน UI, routing, focus, responsive, ปุ่ม reset และการเล่นเสียงจริง
- เครื่องจริง: iOS Safari และ Android Chrome สำหรับ TTS/ไมค์/การหยุดเสียงขณะเปลี่ยนหน้า ระบุรุ่นและ browser version หากยังไม่ทดสอบให้ใส่ “ยังไม่ตรวจ”

## 11. ส่งงานและ Definition of Done

1. รัน `npm test`, `npm run build`, `git diff --check` หลังแก้ เก็บจำนวนผ่าน/ไม่ผ่านตามจริง
2. เปิด preview ที่ build ใหม่จริง ถ้ามี service worker ให้กดอัปเดตแอปและตรวจว่าหน้าแสดงเวอร์ชันล่าสุด อย่าใช้ภาพจาก bundle เก่าเป็นหลักฐาน
3. เก็บ screenshot ใน `docs/bloom/evidence/` อย่างน้อย speaking 390px/desktop, review ก่อนตอบ/หลังตอบ, sentence ที่เลือก 月亮
4. บันทึก TC ที่ผ่าน/ไม่ผ่าน/ยังไม่ทดสอบ พร้อมเหตุผลใน VERIFICATION.md ภาพอย่างเดียวพิสูจน์ cleanup ไมค์ไม่ได้ ให้แนบผล unit test และผลเครื่องจริงแยก
5. Review diff ว่าไม่มีการเปลี่ยน map layout/zoom หรือข้อมูลเดิมโดยไม่ได้ตั้งใจ
6. ส่งสรุปสิ่งที่เปลี่ยนและภาพตัวอย่างให้เจ้าของงานดู ระบุเนื้อหาที่ยังรอตรวจภาษา ห้ามใช้คำว่าเสร็จครบถ้ายังเหลือ
7. ไม่ commit/push/deploy เอง
